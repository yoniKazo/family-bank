# 🏦 הבנק המשפחתי — מדריך הקמה מלא

אפליקציה לניהול הכסף שהילדים שומרים אצל ההורים.
ההורים רושמים הפקדות ומשיכות, והילדים רואים את היתרה וההיסטוריה ושולחים בקשות.

- **האתר**: קבצים סטטיים שמתארחים בחינם ב-GitHub Pages
- **הנתונים וההרשאות**: Supabase (מסד נתונים Postgres, בחינם בתוכנית הבסיסית)
- **התחברות**: חשבון Google

## מה האפליקציה עושה

### הורים
- רואים את כל הילדים, את היתרה של כל אחד ואת הסכום הכולל בקופה
- מוסיפים **הפקדה** או **משיכה**: סכום, תאריך והערה (למשל "דמי כיס", "מתנה מסבתא")
- **עורכים** פעולה שהוזנה בטעות, או **מבטלים** אותה. פעולה מבוטלת לא נמחקת: היא נשארת בהיסטוריה עם קו חוצה ולא נספרת ביתרה
- מקבלים **בקשות** מהילדים ומאשרים או דוחים אותן, עם הערה שהילד יראה. אישור יוצר את הפעולה אוטומטית
- מקבלים **אזהרה** כשפעולה תוריד יתרה מתחת לאפס (אפשר להמשיך בכל זאת)
- מוסיפים ילדים, משנים שמות, מקשרים חשבון Google לכל ילד ומסמנים ילד כ"לא פעיל"

### ילדים
- רואים את היתרה שלהם ואת כל ההיסטוריה עם ההערות
- שולחים בקשת הפקדה או משיכה עם הסבר ("לקנות ספר", "החזרתי בקבוקים")
- רואים את סטטוס הבקשות ואת תשובת ההורים, ויכולים לבטל בקשה שעוד לא טופלה
- **לא** יכולים להוסיף, לערוך או לאשר שום פעולה
- **לא** רואים נתונים של אחים

## שלב 1: יצירת פרויקט ב-Supabase

1. גלשו ל-[supabase.com](https://supabase.com) והתחברו (אפשר עם GitHub).
2. לחצו **New project**.
3. מלאו:
   - **Name**: `family-bank`
   - **Database Password**: סיסמה חזקה. שמרו אותה, אבל האפליקציה לא צריכה אותה
   - **Region**: `Central EU (Frankfurt)`, הקרוב ביותר לישראל
4. לחצו **Create new project** וחכו דקה-שתיים עד שהפרויקט מוכן.
5. היכנסו ל-**Project Settings** (גלגל שיניים בתפריט הצד) ← **API** (או **Data API** / **API Keys**, תלוי בגרסת הממשק), והעתיקו:
   - **Project URL**: נראה כמו `https://abcdefghijk.supabase.co`
   - **anon public key** (ארוך, מתחיל ב-`eyJ...`) **או** **publishable key** (מתחיל ב-`sb_publishable_...`). שניהם עובדים

> 🔐 **האם זה בטוח לשים את המפתח באתר ציבורי?** כן. זה מפתח ציבורי שנועד לדפדפן. ההגנה על הנתונים לא תלויה בו, אלא בהרשאות שבמסד הנתונים (ראו [איך זה עובד](#איך-זה-עובד-מאחורי-הקלעים)).
> ⛔ **לעולם אל תשימו באתר את `service_role` key / `secret` key.** הוא עוקף את כל ההרשאות.

## שלב 2: הרצת מסד הנתונים

1. פתחו את הקובץ `supabase/schema.sql` בעורך טקסט.
2. גללו לסוף הקובץ ומצאו:
   ```sql
   insert into public.members (email, role, display_name) values
     ('parent1@gmail.com', 'parent', 'אבא'),
     ('parent2@gmail.com', 'parent', 'אמא')
   ```
3. החליפו את שני המיילים במיילים **האמיתיים** שלך ושל אשתך, בדיוק כמו שהם בחשבון Google. אפשר גם לשנות את השמות "אבא" / "אמא".
4. ב-Supabase, לחצו בתפריט הצד על **SQL Editor** ← **New query**.
5. העתיקו את **כל** תוכן הקובץ, הדביקו ולחצו **Run** (או `Ctrl+Enter`).
6. אמורה להופיע ההודעה `Success. No rows returned`.

**בדיקה שהכול נוצר:** לחצו על **Table Editor**. אמורות להופיע 4 טבלאות: `children`, `members`, `transactions`, `requests`. בטבלה `members` אמורות להיות שתי שורות עם המיילים שלכם.

> אם Supabase מציג אזהרה על "destructive operations", זה בגלל פקודות `drop policy if exists`. זה בטוח, ולוחצים לאשר.
> מותר להריץ את הקובץ שוב בעתיד (למשל אחרי עדכון). הוא לא מוחק נתונים קיימים.

## שלב 4: הגדרת התחברות עם Google

### 4א. יצירת פרויקט ב-Google Cloud
1. גלשו ל-[console.cloud.google.com](https://console.cloud.google.com).
2. למעלה, ליד הלוגו, לחצו על בחירת הפרויקט ← **New Project**.
3. שם: `family-bank` ← **Create**. ודאו שהפרויקט החדש נבחר למעלה.

### 4ב. מסך ההסכמה (OAuth consent screen)
1. בתפריט: **APIs & Services** ← **OAuth consent screen** (בממשק החדש זה נקרא **Google Auth Platform** ← **Branding** / **Audience**).
2. לחצו **Get started** / **Configure**.
3. מלאו:
   - **App name**: `הבנק המשפחתי`
   - **User support email**: המייל שלך
   - **Audience / User type**: **External**
   - **Developer contact**: המייל שלך
4. בהרשאות (**Scopes / Data access**) לא צריך להוסיף כלום. ברירת המחדל (`email`, `profile`, `openid`) מספיקה.
5. **חשוב, פרסום האפליקציה:** במסך **Audience** לחצו **Publish app** ← **Confirm**.
   - כל עוד האפליקציה במצב **Testing**, רק מי שמופיע ברשימת **Test users** יכול להתחבר (עד 100 משתמשים).
   - עם ההרשאות הבסיסיות בלבד, **לא נדרש** אימות של גוגל כדי לפרסם.
   - אם מעדיפים להשאיר במצב Testing, הוסיפו ב-**Test users** את המיילים של כל בני המשפחה.

### 4ג. יצירת מפתח OAuth
1. **APIs & Services** ← **Credentials** (או **Google Auth Platform** ← **Clients**).
2. **Create credentials** ← **OAuth client ID**.
3. **Application type**: `Web application`
4. **Name**: `family-bank-web`
5. **Authorized JavaScript origins** ← **Add URI**:
   ```
   https://<שם-המשתמש-שלך>.github.io
   ```
   (בלי `/family-bank` ובלי `/` בסוף)
6. **Authorized redirect URIs** ← **Add URI**:
   ```
   https://<project-ref>.supabase.co/auth/v1/callback
   ```
   `<project-ref>` הוא החלק מה-Project URL של Supabase. אפשר גם להעתיק את הכתובת המדויקת מ-Supabase בשלב 5.
7. לחצו **Create** והעתיקו את **Client ID** ואת **Client Secret**.

## שלב 5: חיבור Google ל-Supabase

### 5א. הפעלת Google
1. ב-Supabase: **Authentication** ← **Sign In / Providers** (בגרסאות קודמות: **Providers**).
2. מצאו **Google** ולחצו עליו.
3. הפעילו את **Enable Sign in with Google**.
4. הדביקו את **Client ID** ואת **Client Secret** משלב 4ג.
5. שימו לב לשדה **Callback URL (for OAuth)**. זו בדיוק הכתובת שצריכה להיות ב-Authorized redirect URIs ב-Google. אם הכנסתם משהו אחר, תקנו שם.
6. **Save**.

### 5ב. כתובות מורשות
1. **Authentication** ← **URL Configuration**.
2. **Site URL**:
   ```
   https://<שם-המשתמש-שלך>.github.io/family-bank/
   ```
3. **Redirect URLs** ← **Add URL**, והוסיפו:
   ```
   https://<שם-המשתמש-שלך>.github.io/family-bank/
   http://localhost:8080/
   ```
   (השנייה לפיתוח מקומי, לא חובה)
4. **Save**.

> ⚠️ ה-`/` בסוף הכתובת חשוב. הכתובת צריכה להיות זהה לכתובת שהאתר רץ ממנה.

## שלב 6: הגדרת האתר והעלאה ל-GitHub Pages

### 6א. מילוי `config.js`
פתחו את `docs/config.js` והחליפו:
```js
export const SUPABASE_URL = 'https://abcdefghijk.supabase.co';   // ה-Project URL
export const SUPABASE_ANON_KEY = 'eyJhbGciOi...';                // ה-anon / publishable key
```

### 6ב. העלאה ל-GitHub
מתוך תיקיית הפרויקט (הריפו המקומי כבר מאותחל):
```bash
cd family-bank
git add -A
git commit -m "Configure Supabase"
git remote add origin https://github.com/<שם-המשתמש-שלך>/family-bank.git
git push -u origin main
```

> **בלי Git?** בדף הריפו ב-GitHub לחצו **uploading an existing file** וגררו את כל תוכן התיקייה `family-bank`. חשוב לשמור על המבנה, עם תיקיית `docs` בשורש.

### 6ג. הפעלת GitHub Pages
1. בריפו: **Settings** ← **Pages** (בתפריט הצד).
2. תחת **Build and deployment** ← **Source**: `Deploy from a branch`.
3. **Branch**: `main`, תיקייה: `/docs` ← **Save**.
4. חכו 1–2 דקות ורעננו. למעלה תופיע ההודעה "Your site is live at ..." עם הכתובת.

## שלב 7: שימוש ראשון

1. גלשו לכתובת האתר ולחצו **כניסה עם Google** עם חשבון הורה.
2. אם מופיע "אין לך עדיין גישה", המייל לא תואם למה שהוכנס ב-`schema.sql` (ראו [פתרון בעיות](#פתרון-בעיות)).
3. עברו לטאב **ניהול** ← **הוספת ילד**:
   - **שם**: שם הילד
   - **חשבון Google של הילד**: אם יש לילד Gmail, הכניסו אותו כאן. אם אין, השאירו ריק וההורים ינהלו לבד
4. חזרו לטאב **ילדים**, לחצו על ילד ← **פעולה חדשה** ← בחרו הפקדה, הכניסו את היתרה הנוכחית שלו עם הערה כמו "יתרת פתיחה".
5. חזרו על זה לכל ילד.

**בדיקה עם הילד:** הילד נכנס מהמכשיר שלו עם החשבון שלו. הוא אמור לראות רק את היתרה שלו, את ההיסטוריה ואת טופס הבקשה.

## פיתוח והרצה מקומית

אין שלב build. מספיק שרת סטטי:

```bash
# Python
python3 -m http.server 8080 -d docs

# או Node
npx serve docs -l 8080
```

ואז גלשו ל-`http://localhost:8080/`.

> ההתחברות עם Google תעבוד מקומית רק אם הוספתם את `http://localhost:8080/` ל-Redirect URLs ב-Supabase (שלב 5ב).
> פתיחה ישירה של `index.html` מהדיסק (`file://`) **לא** תעבוד, כי מודולים של JS דורשים שרת.

**עדכון האתר:** משנים קבצים ב-`docs/` ← `git commit` ← `git push`. GitHub Pages מתעדכן תוך דקה-שתיים. אם הטלפון מציג גרסה ישנה, סגרו ופתחו את האפליקציה או רעננו.

## ניהול שוטף

### הוספת הורה נוסף (או החלפת מייל של הורה)
הורים מנוהלים **רק** דרך SQL, כדי שאף אחד לא יוכל להפוך את עצמו להורה מתוך האפליקציה. ב-Supabase ← SQL Editor:
```sql
insert into public.members (email, role, display_name)
values ('new.parent@gmail.com', 'parent', 'סבתא');
```
הסרת הורה:
```sql
delete from public.members where email = 'old@gmail.com' and role = 'parent';
```

### ילד שקיבל חשבון Google
טאב **ניהול** ← הכניסו את המייל בשדה Google של הילד ← **שמירה**.

### ילד שכבר לא משתמש (למשל פתח חשבון בנק אמיתי)
טאב **ניהול** ← בטלו את הסימון **פעיל** ← **שמירה**. הילד נעלם מהמסך הראשי ולא יכול להתחבר, וההיסטוריה שלו נשמרת.

### תיקון פעולה שגויה
במסך הילד, ליד הפעולה ← **✎** ← משנים סכום, תאריך או הערה, או מסמנים **הפעולה מבוטלת**. המערכת רושמת מי ערך ומתי.

### גיבוי
ב-Supabase ← **Table Editor** ← בוחרים טבלה ← **Export** ← CSV. כדאי לגבות מדי פעם את `transactions`, `children` ו-`requests`.

> בתוכנית החינמית, Supabase **משהה** פרויקט שלא היה בו שימוש שבוע. אם זה קורה, נכנסים ללוח הבקרה ולוחצים **Restore**. הנתונים לא נמחקים. שימוש רגיל באפליקציה פעם בכמה ימים מונע את זה.

## איך זה עובד מאחורי הקלעים

### טבלאות
| טבלה | מה יש בה |
|---|---|
| `children` | הילדים: שם, האם פעיל |
| `members` | רשימת ההרשאות: מייל ← תפקיד (`parent` / `child`), ולילד גם לאיזה ילד הוא שייך |
| `transactions` | כל הפעולות: סכום (חיובי = הפקדה, שלילי = משיכה), תאריך, הערה, האם בוטלה, מי יצר ומי ערך |
| `requests` | בקשות הילדים: סוג, סכום, הסבר, סטטוס, תשובת ההורה |
| `balances` (view) | היתרה של כל ילד, מחושבת מסכום הפעולות שלא בוטלו |

### אבטחה
כל ההרשאות נאכפות **בתוך מסד הנתונים** באמצעות **Row Level Security (RLS)**, ולא בקוד שבדפדפן. גם אם מישהו פותח את ה-DevTools ושולח בקשות ישירות עם המפתח הציבורי, הוא לא יכול לעקוף אותן:

- **מי שלא ברשימת `members`** מתחבר עם Google אבל לא רואה שום נתון
- **ילד** רואה רק את השורות של עצמו, ולא רואה פעולות שבוטלו
- **ילד** יכול ליצור רק בקשה, ורק על שם עצמו
- **רק הורה** יכול ליצור או לערוך פעולות, לנהל ילדים ולאשר בקשות
- **הורים** מוגדרים רק ב-SQL, ומהאפליקציה אפשר לנהל רק חשבונות של ילדים

### החלטות עיצוב
- **יתרה מחושבת ולא שמורה**: אין מצב שהיתרה "נסחפת" ולא מתאימה להיסטוריה.
- **ביטול במקום מחיקה**: שום פעולה לא נעלמת. אפשר תמיד לראות מה היה ולשחזר.
- **"מי עשה מה" לא ניתן לזיוף**: השדות `created_by` / `updated_by` נקבעים בטריגר במסד הנתונים לפי החשבון המחובר, ולא לפי מה שהדפדפן שולח.
- **אישור בקשה אטומי**: הפונקציה `decide_request` נועלת את הבקשה, יוצרת את הפעולה ומעדכנת סטטוס בפעולה אחת. אי אפשר לאשר פעמיים, ואי אפשר שהבקשה תאושר בלי שהפעולה נרשמה.
- **תאריכים לפי שעון ישראל**: "היום" מחושב לפי `Asia/Jerusalem`, גם כשהשרת עובד ב-UTC.
- **בלי build ובלי תלויות**: JavaScript רגיל, והספרייה של Supabase נטענת מ-CDN. קל לתחזק ולשנות.
